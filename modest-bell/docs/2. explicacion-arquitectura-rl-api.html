01 · Flujo Completo de una Petición

Cinco pasos conectan la imagen de la hoja con la memoria del agente RL

El backend en app.py no mezcla los modelos: la CNN Keras solo predice la enfermedad, el agente RL solo decide la estrategia, y el servicio LLM solo redacta el texto final. Al cerrar el ciclo, POST /feedback actualiza la tabla Q sin reentrenar ni la CNN ni el LLM.

02 · Fundamentos de Aprendizaje por Refuerzo

RL aprende por prueba, error y recompensa: aquí opera como Bandido Contextual

Reinforcement Learning (RL) es una rama del Machine Learning donde un agente aprende a tomar decisiones interactuando con un entorno. A diferencia del aprendizaje supervisado (que necesita ejemplos etiquetados de "la respuesta correcta"), el RL solo recibe una señal numérica llamada recompensa después de actuar.

En este proyecto, el algoritmo exacto es un Contextual Multi-Armed Bandit (Bandido Multibrazo Contextual) implementado en ContextualBanditAgent (rl_agent.py:22). ¿Por qué "contextual"? Porque la mejor acción depende del contexto actual (la enfermedad detectada).

Contexto = Estado (s)

Qué ve el agente

La clase predicha por la CNN: Potato___Early_blight, Potato___Late_blight o Potato___healthy.

Decisión = Acción (a)

Qué elige el agente

El estilo del prompt enviado al LLM: tecnico (FRAC/dosis), practico (pasos en campo) o ecologico (MIP orgánico).

Señal = Recompensa (r)

Cómo aprende

Las estrellas del usuario (1 a 5) convertidas a escala [−1.0, +1.0] ajustan el valor esperado Q(s, a).

El dilema Exploración vs. Explotación (política ε-greedy)

Si el agente eligiera siempre la estrategia con mayor puntaje Q, jamás descubriría si otra estrategia gusta más. Por eso select_action() (rl_agent.py:199) tira un número aleatorio entre 0 y 1:

Condición Probabilidad Modo Comportamiento en código (rl_agent.py:207-218)
random() < 0.2 20% Exploración Elige al azar entre las 3 acciones (tecnico, practico, ecologico) para probar alternativas.
random() ≥ 0.2 80% Explotación Elige la acción con mayor Q(s, a) para esa enfermedad (si hay empate, desempata al azar).

03 · Anatomía de la Llamada a la API

La estrategia elegida por RL se inyecta en el System Prompt antes de salir a Internet

El LLM no "sabe" RL ni lee la tabla Q. Quien traduce la decisión del agente en instrucciones concretas es build_prompts() en llm_service.py:91. Según la estrategia (tecnico, practico o ecologico), cambia el rol del system_prompt, mientras el user_prompt lleva el diagnóstico numérico de la CNN.

Endpoint Cuándo se llama Qué envía al LLM Nota clave para preguntas
POST /predict Al subir la hoja de papa Diagnóstico CNN + estrategia del agente RL (o override manual) temperature=0.4, máximo 700 tokens de salida.
POST /regenerate Al cambiar estrategia en UI Mismo diagnóstico guardado en frontend + nueva estrategia No vuelve a correr la CNN; ahorra cómputo y tiempo.
POST /chat Preguntas de seguimiento Diagnóstico + recomendación inicial + últimos 8 turnos Mantiene el rol de la estrategia activa en formato Markdown.

04 · Cómo se hace Feedback al Modelo mediante RL

Cada calificación de 1 a 5 estrellas mueve el valor Q(s, a) un 20% hacia la recompensa

Cuando el usuario califica la recomendación en la interfaz, el frontend envía {disease_id, strategy, rating, comment} a POST /feedback (app.py:375). Por dentro, rl_agent.update() ejecuta exactamente tres operaciones matemáticas y una escritura atómica en disco:

Paso 1 · Normalización

r = (rating − 3) / 2.0

1★ = −1.0 · 2★ = −0.5 · 3★ = 0.0 (neutral) · 4★ = +0.5 · 5★ = +1.0.

Paso 2 · Regla de actualización

Q ← Q + α · (r − Q)

Con α = 0.2, el agente no olvida todo de golpe: promedia exponencialmente el historial con la nueva opinión.

Paso 3 · Persistencia atómica

mkstemp → fsync → replace

Bajo threading.Lock, escribe un archivo temporal y lo reemplaza sobre data/rl_policy.json para evitar corrupción.

Estado real observado en data/rl_policy.json

El archivo actual del proyecto registra 1 feedback real: estado Potato___Early_blight, acción ecologico, calificación 5 estrellas (r = +1.0). Como Q_before era 0.0, el cálculo fue 0.0 + 0.2 × (1.0 − 0.0) = 0.2. Por eso hoy, en 80% de los casos (explotación), para Tizón Temprano el agente preferirá ecologico.

06 · Preparación para la Defensa

Preguntas que probablemente te harán mañana y respuestas exactas

1. ¿El Aprendizaje por Refuerzo modifica los pesos de la CNN o del modelo de Gemini/DeepSeek?
No. La CNN (.keras) está congelada en inferencia (training=False, torch.no_grad()) y la API de Gemini/DeepSeek es un servicio externo sin fine-tuning. El agente RL solo aprende qué estrategia de prompt (tecnico, practico o ecologico) maximiza la satisfacción del usuario para cada enfermedad, guardando 9 valores flotantes en data/rl_policy.json.
2. ¿Por qué usar un Contextual Bandit y no Q-Learning completo o Deep RL?
Porque cada diagnóstico es un episodio independiente de un solo paso: la recomendación que das hoy para una hoja no cambia la enfermedad de la siguiente hoja que suba otro agricultor (no hay transición de estado s → s' ni factor de descuento γ). Un Bandido Contextual converge rápido con pocos feedbacks humanos, sin necesitar miles de datos ni GPU.
3. ¿Qué pasa si falla Internet, se acaba la cuota de Gemini o no hay API Key?
llm_service.py nunca deja al usuario sin respuesta: primero intenta una cascada de modelos Gemini (gemini-2.5-flash y fallbacks) con timeout de 15s; si todos fallan o la clave no es válida, activa build_structured_fallback(), que entrega una guía agronómica local adaptada a la enfermedad y estrategia, garantizando más de 200 caracteres y marcando is_fallback: true.
4. ¿Qué ocurre si el usuario califica con 1 estrella una estrategia que ya tenía buen puntaje?
La calificación de 1 estrella produce recompensa negativa r = (1 − 3) / 2.0 = −1.0. Con α = 0.2, Q(s, a) baja un 20% de la distancia hacia −1.0. Si cae por debajo de otra estrategia, en la siguiente explotación (80% de las veces) el agente cambiará automáticamente a la nueva estrategia ganadora.
5. ¿Se pierde lo que aprendió el agente si se reinicia el servidor o hay dos usuarios a la vez?
No se pierde ni se corrompe. Al arrancar, ContextualBanditAgent carga data/rl_policy.json. Cada actualización usa un threading.Lock() para evitar condiciones de carrera entre peticiones simultáneas y escribe mediante archivo temporal + os.fsync() + os.replace() (escritura atómica).
